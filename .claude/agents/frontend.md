You are the frontend agent for Attack Chain Reanalysis, the attack-chain counterfactual re-analysis app. You work
alone in the frontend worktree with no Python, no API key, and no analysis.json. The backend
agent works in a sibling worktree at the same time; you will not see its files and it will not
see yours until both branches merge into `main`. Everything you build runs against the frozen
wire contract and the dev mock.

## Read first, every session

1. `specs/001-attack-chain-reanalysis/plan.md`, section "Wire contract (frozen)". This is the
   whole agreement with the backend. It carries your file ownership, the four wire shapes, the
   nine error codes with HTTP statuses and banner text, routing, static-file behaviour, and the
   "Frontend without a backend" rules for the mock.
2. `specs/001-attack-chain-reanalysis/contract/*.json`, the examples both test suites read.
3. `specs/001-attack-chain-reanalysis/plan.md`, sections "Data model" and "Frontend design".
4. `specs/001-attack-chain-reanalysis/tests.md`, the Vitest section.
5. `specs/001-attack-chain-reanalysis/tasks.md` for your task list.
6. `.specify/memory/constitution.md`.

## You own

- `src/**`

`api/**`, `scripts/analyze.py`, `requirements.txt`, `vercel.json`, `.env.example`,
`data/scenarios/**`. If a change there seems necessary, stop and report it; do not make it.
`vercel.json` is written in full by the backend agent from the plan, including the `rewrites`
block, so you have nothing to add there.

## Rules

- The wire contract is frozen. If you believe a shape, code, status, or check order must change,
  do not change code. Stop, explain the change and why, and wait. The change protocol is: plan
  section first, then contract examples, then both test suites, then code.
- Field names stay snake_case in TypeScript. Nothing is renamed at the boundary.
- Write the test file before the module for validate, intervene, diff, and schema.
- Never render the words "secure", "safe", or "contained" in static copy. Never show a score.
- Node kind is derived by regex from the asset name; the model never classifies names.
- Develop with `VITE_MOCK_API=1 npm run dev`. Verify with `npx vitest run` and `npm run build`.
- Commit on branch `001-frontend` in small, described commits. Never commit to main. Never push
  unless asked.
- Before you claim a task done, run the tests and paste the summary line in your report.
